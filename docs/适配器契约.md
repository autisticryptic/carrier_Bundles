# 平台适配器契约

iOS 与 Android 适配器可以使用不同语言和解析库，但只能向根 `schema.sql` 定义的规范表输出数据。

## 构建流程

```text
iOS 固件 ── iOS adapter ──┐
                           ├── 新 SQLite ── 图标匹配/嵌入 ── seal ── 原子发布
Android 固件 ─ Android adapter ─┘
NekokoLPA2/operator-icons ───────────────────┘
```

每次发布必须创建新文件，不允许打开上一个 release 后增量修改。建议文件名包含 release id，例如 `carrier-bundles-2026.08.07.sqlite3`。

当前实施顺序与数据源选择见 [`提取器路线图.md`](./提取器路线图.md)。顺序不改变本契约：Pixel、iOS、Samsung 和 modem 解析器都只是输入适配器，不拥有私有 schema。

## 获取和解包要求

- 优先使用官方发布的完整固件：Pixel Factory Image/完整 OTA、Apple IPSW、Samsung FUS 固件。
- 第三方元数据服务只用于发现官方制品 URL；`source_uri` 尽量记录最终厂商/CDN 地址。
- 下载后记录制品哈希、设备、OS/build、baseband 版本、解析器名称和版本。
- 增量 OTA、真实设备分区 dump 和 live EFS 不作为首版输入。
- 解包目录和大型固件是临时构建输入，不嵌入 SQLite，也不提交仓库。
- 适配器必须允许只解析已经下载的本地制品，保证离线复现和 fixture 测试。

## 字段证据要求

每个进入规范表的重要字段必须能关联 `source_snapshots`、`profile_sources`，并在需要时通过 `field_evidence` 保留原始键路径、原始值和 confidence。

- 文件中直接存在：`evidence_kind='extracted'`。
- 依据标准计算：`evidence_kind='standard_derived'`。
- 仅由运营商公开元数据提供：`evidence_kind='operator_metadata'`。
- 反编译或逆向语义未确认：不得写入规范列，只能在白名单允许时写入 `raw_config_values`。
- 未发现：保持 `NULL`/无记录，禁止用空字符串、客户端默认或猜测值补齐。

## ID 与合并规则

- `carrier_id`：稳定 slug，不包含固件版本，如 `cn-china-mobile`。
- `profile_id`：稳定、可重建，建议为 `carrier_id + 匹配范围 + 配置变体`。
- 相同 profile 可有多个 `profile_sources`，表示 iOS/Android/标准来源共同佐证。
- 同字段冲突时不静默覆盖：选择值进入规范表，所有候选通过 `field_evidence` 保留来源和可信度。
- 标准域名推导必须标为 `standard_derived`，不能伪装成固件实测值。
- `NULL` 表示未知；`0` 表示来源明确关闭；两者不可互换。
- 三方 ROM、归档解析器和无明确许可证的研究项目只作格式参考或辅助证据，不作为运行时依赖，未经确认也不能覆盖官方固件提取值。

## 允许输出

- 固件/配置包的版本、哈希和公开来源。
- 运营商公共标识、PLMN、公开匹配前缀和配置适用条件。
- IMS、VoLTE、VoNR、VoWiFi、ePDG/IKE/SIP 的静态网络配置。
- 经过白名单过滤的厂商原始静态键值。

## 禁止输出

- 用户线路和 SIM 绑定。
- 实际 IMSI、ICCID、MSISDN、IMEI、IMPI、IMPU。
- Ki、OP/OPc、PIN、RAND、AUTN、RES、CK、IK、AUTS 或会话密钥。
- 注册尝试、SIP Call-ID、动态 P-CSCF、分配地址、SPI 和临时端口。
- 应用自己的重试/伪装/兼容 workaround，除非它是固件中明确提取的运营商静态要求。

## 发布与读取

构建期间数据库可写。完成 iOS/Android 导入和校验后运行以下命令；它会先更新 NekokoLPA2、根据已写入的运营商规则嵌入图标，再封存数据库：

```bash
python3 tools/seal_db.py data/carrier-bundles-2026.08.07.sqlite3
```

消费者必须使用只读 URI：

```text
file:carrier-bundles-2026.08.07.sqlite3?mode=ro&immutable=1
```

推荐先查询 `v_carrier_catalog`、`v_access_catalog` 和 `v_endpoint_catalog`。需要显示图标时，再用 `asset_id` 查询 `v_visual_asset_catalog`，其中 `asset_data` 是可直接解码的原始 PNG/SVG BLOB。
